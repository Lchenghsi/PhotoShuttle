## 1. 项目概述

简单传是一个**完全本地运行**的 iPhone 照片速览与导出工具：单文件 exe（内置 Node.js 运行时与全部页面资源），通过 USB 数据线直连 iPhone，在浏览器/应用窗口中秒级浏览近两周的照片与视频缩略图，并支持按日期一键导出原片到资源管理器。

核心设计约束：

- **隐私**：照片只在手机与本机之间传输，无任何云端中转、无遥测、无账号体系
- **轻量**：运行时零第三方依赖（`package.json` 无 `dependencies`），构建期工具链独立于运行期
- **快**：不做全量备份工具，聚焦"近两周速览 + 按需导出"场景

## 3. 架构与技术选型

```
浏览器 / 独立应用窗口（Edge/Chromium --app 模式，PWA 可安装）
   │  HTTP(127.0.0.1:5178) + SSE
本地服务（Node.js，单文件 exe 内嵌）
   │  纯 JS 实现 Apple 协议栈（无原生模块、无外部进程依赖核心链路）
usbmuxd (127.0.0.1:27015，Apple 移动设备服务提供)
   └─ lockdown (设备 62078, TLS) ── StartService ── AFC 连接池 ×16
        ├── /DCIM/…                                   原片（仅导出/预览时读取）
        ├── /PhotoData/Thumbnails/V2/DCIM/…/5005.JPG  照片缩略图（设备现成）
        └── /PhotoData/Thumbnails/VideoKeyFrames/…    视频关键帧
```

关键技术决策与依据：

| 决策 | 依据 |
| --- | --- |
| 直读 iOS 自带缩略图库（`/PhotoData/Thumbnails/V2/`），不解码 HEIC | 缩略图读取实测约 1000 张/秒（USB 3），远快于"下载原片再解码"路径 |
| 索引"从新到旧"扫描 + 连续 500 个旧文件提前收工 | 目录枚举 <100ms，stat 约 4000~6000 条/秒；近期模式无需全库扫描 |
| AFC 连接池 ×16 | AFC 协议限制单连接单请求，并发池是吞吐的唯一来源；缩略图/元数据/导出分道限流互不抢占 |
| 零运行时依赖 | 供应链风险最小化；构建期依赖（esbuild/postject/resedit/heic2any）不进入产物运行路径 |
| 单文件 exe 分发（Node SEA 注入） | 终端用户免装 Node.js；页面资源全部内嵌 |

## 4. 功能清单与验证证据

以下数据均为开发机 + 真机（iPhone，USB 3）实测记录。

### 4.1 核心链路

| 验证项 | 方法 | 实测结果 |
| --- | --- | --- |
| 相册索引（近两周） | HTTP 接口计时 | 755 项，服务端 74~341ms（视库内容变动） |
| 索引持久化 | 冷/热启动对比 | 冷 13.2s（全量扫描）→ 温 0.7s → **0.25s（stats=0，快照全命中）** |
| 缩略图 | 单张计时 + 字节数 | 53~72KB JPEG，**11.5ms**（缓存命中）；批量约 1000 张/秒量级 |
| 导出（单文件） | 字节级比对 | 2.9MB PNG，93ms，**与设备端字节数完全一致** |
| 导出（并发池） | 10 文件批量 | count=8（含 1 组 Live Photo 配对合并，语义正确），failed=0 |
| CLI 导出 | `export --today --json` | 172 文件 / 7.4GB，JSON 摘要正确，退出码 0 |
| 视频时长角标 | moov/mvhd 解析 | 724/724 个视频获得时长（头 128KB + 尾 256KB 两次小读） |
| 自定义图标 | 像素取样 | ExtractAssociatedIcon 读出蓝色渐变像素（非 Node 默认绿） |

### 4.2 质量验证方法

- **协议层交叉验证**：自实现二进制 plist 编解码器与 Python `plistlib` 互测（双向解析一致）；usbmux/lockdown 与真机实测联通。
- **字节级导出校验**：导出文件与设备端标称大小逐一比对；不一致者计入 `suspicious`（疑似 iCloud 占位图，见 §5.3）。
- **图标像素级校验**：提取关联图标位图并采样像素，确认非默认图标。
- **持久化回归**：连续三次重启对比 stat 次数（1260 → 505 → 42 → 0）。
- **端口处理**：第二实例唤起已有窗口（exit 0）；无关程序占用端口时自动顺延（实测 5180→5181）。

## 5. 安全、隐私与事件记录

### 5.1 安全软件事件与整改（重要）

| 事件 | 根因 | 整改措施 | 现状 |
| --- | --- | --- | --- |
| Windows Defender 报毒：`Trojan:VBS/Obfuse.A!MTB`、`Trojan:VBS/AgentTesla.GVC!MTB`（2026-09-08，用户手动放行） | 程序曾生成 VBS 启动器（`Wscript.Shell.Run` 以**隐藏窗口**拉起 exe）——该模式是恶意 VBS 落地器的典型启发式特征，属**误报** | 彻底移除 VBS 启动器方案：桌面快捷方式直接指向 exe（控制台最小化运行）；启动时自动清理遗留 `.vbs` 文件；构建脚本不再生成任何 VBS | 已修复并验证：全盘无 `.vbs` 残留。**用户可撤销此前对这两条的手动放行**，不影响使用 |

说明：应用使用未付费签名的二进制，SmartScreen 首次提示为预期行为（使用说明与 README 已向用户披露）。

### 5.2 运行事故与恢复记录

| 事故 | 根因 | 恢复 | 预防 |
| --- | --- | --- | --- |
| 一次清理命令误删用户 `settings.json`（导出目录设置等） | 清理通配符范围过宽 | 依据开发记录中的准确内容立即恢复，重启验证通过 | 清理命令不再使用宽通配符作用于用户数据目录 |
| 旧版页面脚本被 Service Worker 缓存钉死（新功能"视频时长角标"不可见） | SW 缓存名含占位符，且注释中也含同名占位符，`String.replace` 仅替换首处导致缓存名从未更新 | 占位符改为 `replaceAll` 并换措辞；构建脚本向 sw.js 注入构建时间戳缓存名，每次打包强制换缓存 | 已列入开发记忆，后续构建自动生效 |

### 5.3 隐私与数据声明

- 照片数据流：iPhone USB → 本机磁盘，**无云端环节**；程序不发起任何外部网络请求
- 本地数据：`C:\Users\<用户>\.jiandanchuan\`（设置 + 日志 + 缩略图缓存），可随时整体删除
- 端口：仅监听 `127.0.0.1:5178`（被占用时顺延并记录日志），不监听外网接口
- 原生文件夹选择、导出定位等操作通过 PowerShell 调用系统组件完成，不引入第三方二进制

### 5.4 权限与依赖

- 无管理员权限要求
- 运行期依赖：Apple 移动设备服务（Apple Devices 应用或 iTunes 提供，业界标准前置条件）
- 构建期开发依赖：esbuild、postject、resedit、heic2any（均不进入运行路径）

## 6. 评估后放弃的方案（决策记录）

| 方案 | 放弃原因（评审要点） |
| --- | --- |
| 安卓（MTP/PTP）适配 | WPD 互操作在脚本层存在跨程序集接口副本问题；设备管理器枚举不稳定；WIA 连接异常。已有社区方案亦无设备级缩略图的可靠通路。经真机实测后放弃，决策与失败细节已归档 |
| Electron 桌面壳 | 安装体积 ~250MB；已有 PWA + 应用模式窗口以零体积达成同等窗口体验 |
| 增量备份（只导出新增） | 需要全库索引（违背"近两周速览"性能设计）；产品定位漂移为备份工具。替代方案：CLI 按日期导出接口（已实现，见 §4.1） |
| 相册/收藏浏览 | 依赖未文档化的 Photos.sqlite schema，随 iOS 版本漂移，维护成本高 |
| iCloud 占位图预检 | AFC 层无可靠的"是否在 iCloud"标志位。降级为导出时字节校验（已实现，见 §5.3/§4.1） |
| 照片删除 | AFC 删除存在 iOS 相册数据库"幽灵条目"风险，售后负担高 |
| rcedit 修改 exe 图标 | rcedit-x64.exe 对 SEA 注入后的 exe 持续挂起；已改用纯 JS resedit 写入 PE 资源（已验证） |

## 7. 已知限制

- HEIC/HEIF 原片无法在浏览器直接渲染，预览显示设备缩略图（导出为完整原片）；已内置 WASM 解码器提供原片级预览，个别 HDR/特殊编码可能解码失败并回退
- 在 iPhone 上刚编辑、尚未完成后台渲染的视频，导出可能失败（iOS 端文件未就绪）；等待渲染完成后重试即可（README 已提示）
- 未签名二进制的 SmartScreen 首次提示（见 §5.1）
- 端口 5178 被第三方占用时自动顺延端口，此时通过"安装 PWA"方式创建的开始菜单图标需重新安装（桌面快捷方式不受影响）
